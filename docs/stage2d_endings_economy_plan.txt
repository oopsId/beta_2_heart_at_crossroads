STAGE 2D — КОНЦОВКИ И ЭКОНОМИКА
Текущая схема -> схема, которая должна прийти ей на смену

Статус документа: дизайн-контракт для Stage 2D.
Цель: сначала зафиксировать фактическое состояние игры, затем менять код строго по описанной ниже целевой схеме.

============================================================
1. ТЕКУЩАЯ СХЕМА КОНЦОВОК
============================================================

Финальный выбор находится в chapter10, scene 5.
Игроку показываются шесть вариантов, каждый содержит endingId:
- freedom_with_dima
- silence_with_mark
- summit_with_sergey
- friendship_above_all
- lonely_path
- new_start

Сейчас движок проверяет finals.json -> requirements ДО применения эффектов финального выбора.
Если requirements не выполнены, вариант остаётся видимым, но становится заблокированным/disabled.
Именно поэтому в эмоциональном пике появляются замки.

Эффекты самого финального ответа не помогают открыть соответствующий путь, потому что eligibility уже проверена.

Достижимые диапазоны, по последнему reachability-анализу:
- crown: 0..9
- heart: 0..23
- leaf: 0..21
- relationships.dima: 0..5
- relationships.mark: 0..9
- relationships.sergey: 0..7
- relationships.vika: -4..2

Текущие концовки:

1) freedom_with_dima / «Свобода с Димой»
Требования ДО финального выбора:
- heart >= 15
- relationships.dima >= 2
Эффект финального ответа «Уйти с Димой»:
- heart +2
- relationships.dima +2
Доля eligible projected states: 26.72%

2) silence_with_mark / «Тишина с Марком»
Требования ДО финального выбора:
- heart >= 15
- leaf >= 10
- relationships.mark >= 4
Эффект финального ответа «Остаться с Марком»:
- heart +2
- leaf +1
- relationships.mark +2
Доля eligible projected states: 2.39%
Это самый очевидный математический перекос текущей системы: путь формально существует, но сочетание трёх высоких порогов делает его почти недоступным.

3) summit_with_sergey / «Вершина с Сергеем»
Требования ДО финального выбора:
- crown >= 6
- relationships.sergey >= 3
Эффект финального ответа «Довериться Сергею»:
- crown +2
- relationships.sergey +2
Доля eligible projected states: 32.35%

4) friendship_above_all / «Дружба превыше всего»
Требования ДО финального выбора:
- leaf >= 15
- relationships.vika >= 1
Эффект финального ответа «Остаться с Викой»:
- leaf +2
- relationships.vika +2
Доля eligible projected states: 9.90%
Учитывая очень узкий диапазон отношений с Викой (-4..2), путь тоже заметно пережат.

5) lonely_path / «Одинокий путь»
Требования ДО финального выбора:
- crown >= 5
- crown + 2 >= heart
- crown + 2 >= leaf
Эффект финального ответа «Уйти одной»:
- crown +2
Доля eligible projected states: 3.65%

6) new_start / «Новый старт»
Текущие executable requirements:
- all: []
- fallback: true
Эффект финального ответа «Мне нужно время»:
- crown +1
- heart +1
- leaf +1
Доля eligible projected states: 100%

Важно: id финального выбора сейчас называется "premium", но никакой стоимости в бриллиантах у него больше нет. Это историческое имя и оно вводит в заблуждение.

Главные проблемы текущей схемы концовок:
- замки появляются ровно в эмоциональном пике;
- финальный осознанный выбор игрока может быть запрещён статистикой;
- relationships и personality stats одновременно используются как жёсткие ворота;
- Марк математически почти исчезает;
- Вика тоже слишком узкая;
- new_start одновременно является настоящей концовкой и техническим гарантированным fallback;
- финальные choice-effects логически запаздывают: игрок заявляет намерение, но это намерение не участвует в доступности пути;
- пользовательское ощущение «где же выбор?» противоречит текущей gate-модели.

============================================================
2. ТЕКУЩАЯ ЭКОНОМИКА
============================================================

Бриллианты являются постоянным профильно-подобным банком между прохождениями.
Ключ persistent bank: diamondBank в namespaced localStorage beta_2.
Continue обязан брать банк, а не старое число diamonds из сохранённого run.

Текущее стартовое значение для beta:
- 70 бриллиантов.

Текущая награда за полное прохождение:
- +100 бриллиантов.
- награда выдаётся после завершения финальной сцены/эпилога, когда completionCount реально увеличился.
- вход в ending сам по себе награду не даёт.

Сейчас значение 70 технически задублировано:
- старый foundation всё ещё создаёт fresh run с diamonds = 10;
- поздний replay/progression слой Stage 0M переопределяет fresh run на 70;
- progression/diamonds.js снова содержит INITIAL_DIAMONDS = 70.
Работает это только потому, что слои загружаются в нужном порядке. В целевой схеме такого быть не должно.

Сюжетная покупка, подтверждённая в текущих данных:
chapter1, scene 3, choice "premium":
- текст: «Что за студия? Расскажи!»
- cost: 5
- это дополнительная реплика/ветка, а не обязательный маршрут к финалу.

Финальный choice "Мне нужно время" бриллиантов НЕ стоит.

Галерея:

После первого завершённого прохождения становятся ДОСТУПНЫМИ К ПОКУПКЕ, но не открываются автоматически:
- card_mark_childhood — 50 бриллиантов
- card_katya_and_anna_bff_birthday — 50 бриллиантов

После второго завершённого прохождения становятся ДОСТУПНЫМИ К РУЧНОМУ БЕСПЛАТНОМУ ОТКРЫТИЮ, но не открываются автоматически:
- card_sergey_and_wife
- card_anna_and_dima_final

Ключевая семантика галереи:
"available" != "unlocked".
Прохождение только снимает условие доступности. Само открытие карты всегда является отдельным действием пользователя.

Пример при отсутствии трат:
- старт: 70
- завершено первое прохождение: 170
- можно вручную купить две карточки по 50; после обеих покупок останется 70
- завершено второе прохождение: 170
- две replay-карты теперь можно вручную открыть бесплатно

Если игрок покупал сюжетную реплику за 5, соответствующий баланс уменьшается на 5.

============================================================
3. ЦЕЛЕВАЯ СХЕМА КОНЦОВОК — ЗАМЕНА ТЕКУЩЕЙ
============================================================

Основной принцип:
ФИНАЛЬНЫЙ ВЫБОР НЕ ДОЛЖЕН БЫТЬ ЗАБЛОКИРОВАН.

В chapter10 scene 5 все шесть вариантов всегда видимы и всегда нажимаемы.
Никаких замков, disabled-кнопок и сообщений «вы не заслужили этот путь» в финальном эмоциональном пике.

Новая логика:
1. Перед финальным выбором делается snapshot накопленной истории: stats + relationships.
2. Все шесть финальных вариантов доступны.
3. Игрок выбирает направление сам.
4. endingId определяется непосредственно выбранной кнопкой.
5. Накопленная история не запрещает endingId, а вычисляет скрытое качество/силу выбранного маршрута.
6. После этого применяются effects финального ответа.
7. Показывается выбранная концовка.

Иными словами:
- финальный выбор отвечает на вопрос «чего Анна хочет сейчас?»;
- предыдущие главы отвечают на вопрос «насколько этот выбор подготовлен прожитой историей?».

Предлагаемое внутреннее значение routeStrength:
- strong — история действительно вела к этому пути;
- mixed — часть истории вела туда, часть противоречила;
- impulsive — финальное решение резко расходится с предыдущим прохождением.

routeStrength НЕ блокирует концовку.
На первом этапе он может вообще не показываться пользователю.
Позже он может менять несколько строк эпилога, дополнительную сцену, achievement или memory, не отнимая сам выбор.

Начальная математика routeStrength для Stage 2D:

DIMA
primary: relationships.dima
secondary: heart
strong: dima >= 2 И heart >= 12
mixed: dima >= 1 ИЛИ heart >= 10
иначе: impulsive

MARK
primary: relationships.mark
secondary: heart + leaf
strong: mark >= 3 И (heart >= 10 ИЛИ leaf >= 8)
mixed: mark >= 1 ИЛИ heart >= 8 ИЛИ leaf >= 6
иначе: impulsive

SERGEY
primary: relationships.sergey
secondary: crown
strong: sergey >= 2 И crown >= 4
mixed: sergey >= 1 ИЛИ crown >= 3
иначе: impulsive

VIKA
primary: relationships.vika
secondary: leaf
strong: vika >= 1 И leaf >= 10
mixed: vika >= 0 ИЛИ leaf >= 7
иначе: impulsive

ALONE
primary: самостоятельность, без relationship gate
strong: crown >= 5 И crown + 3 >= heart И crown + 3 >= leaf
mixed: crown >= 4
иначе: impulsive

NEW START
Не должен быть fallback-«дыркой» для недоступных маршрутов.
Это самостоятельный осознанный выбор.
routeStrength для него можно считать neutral/intentional без жёсткого порога.

Перед merge новой математики validator должен вывести распределение strong/mixed/impulsive по достижимым состояниям.
Цель не сделать все strong одинаковыми, а убрать абсурд вроде текущих 2.39% для Марка.
Ориентир для strong романтических/дружеских путей: примерно 15–45% projected states; после реального отчёта пороги можно подвинуть.

Важно:
- user-facing availability каждой из шести концовок = 100%;
- routeStrength = скрытая характеристика истории, не gate;
- diamonds никогда не участвуют в доступности концовки;
- текущие legacyRequirements после перехода удалить как исторический мусор;
- executable requirements больше не должны использоваться UI как замки;
- new_start может оставаться внутренним emergency fallback только как защита от повреждённых данных, но не как пользовательская «единственная разрешённая кнопка».

============================================================
4. ЦЕЛЕВАЯ СХЕМА ЭКОНОМИКИ — ЗАМЕНА ТЕКУЩЕЙ
============================================================

На Stage 2D НЕ придумывать новые цены без отдельного решения.
Для beta сохраняются текущие договорённые числа:
- initial diamonds: 70
- completion reward: 100
- chapter1 optional dialogue: 5
- gallery paid cards: 50 + 50
- replay gallery cards: бесплатно после completionCount >= 2, но только ручное открытие

Что меняется архитектурно:

1. Один источник истины.
Стартовые 70 и reward 100 должны существовать в одном economy config, а не одновременно в foundation, replay-progression и diamonds.js.

2. Fresh run не создаёт собственный независимый баланс.
Он получает актуальный persistent bank.

3. Continue не имеет права воскресить старое число diamonds из run save поверх банка.

4. Все траты должны сразу обновлять persistent bank.

5. +100 начисляется только после реально завершённого прохождения/эпилога.

6. Diamonds используются только для необязательного контента:
- дополнительные реплики/мини-сцены;
- коллекционные карточки;
- будущий bonus content.
Ни одна основная концовка не должна требовать diamonds.

7. Gallery progression остаётся такой:
completionCount 0:
- две карты за 50 ещё недоступны;
- две replay-карты недоступны.

completionCount 1:
- две карты за 50 становятся покупаемыми;
- они НЕ открываются автоматически;
- replay-карты всё ещё недоступны.

completionCount >= 2:
- две replay-карты становятся доступными к ручному бесплатному открытию;
- они НЕ открываются автоматически.

8. "available", "affordable" и "unlocked" должны быть разными состояниями.

9. Финальный choice "Мне нужно время" переименовать технически с id "premium" на смысловой id (например new_start/time), потому что он бесплатный и не является premium purchase.

============================================================
5. ACCEPTANCE CRITERIA STAGE 2D
============================================================

Концовки:
- в chapter10 scene 5 нет пользовательских замков;
- все шесть ending choices нажимаемы при любом валидном достижимом state;
- нажатая кнопка всегда ведёт в выбранный endingId;
- предыдущие решения вычисляют routeStrength, но не отменяют выбор;
- validator отдельно проверяет routeStrength distribution;
- Марк больше не имеет искусственного user-facing 2.39% availability;
- new_start остаётся настоящей концовкой, а не наказанием за недостаточные статы;
- legacyRequirements удалены после миграции;
- никакие diamonds не участвуют в ending eligibility.

Экономика:
- чистый новый профиль получает ровно 70;
- paid choice за 5 уменьшает банк ровно на 5 и переживает Continue/reload;
- завершение полного финала даёт ровно +100 после эпилога;
- повторное открытие ending без нового завершённого run не создаёт дополнительную награду;
- после первого completion две 50-diamond gallery cards только становятся доступными;
- после второго completion две replay cards только становятся доступными к ручному открытию;
- никакая gallery card не auto-unlock;
- один central economy source содержит 70/100 и правила глобальной экономики;
- старый foundation default diamonds=10 и дублирующий Stage 0M starting balance больше не определяют реальный баланс.

============================================================
6. ЧТО НЕ ДЕЛАЕМ В STAGE 2D
============================================================

- не переписываем сами тексты финалов;
- не добавляем новые концовки только ради математики;
- не вводим платные концовки;
- не меняем 70/100/50/5 без отдельного решения;
- не используем missing audio как повод менять сюжет;
- не auto-unlock галерею;
- не возвращаем visible route locks.

Этот файл является исходной точкой для реализации Stage 2D. Если реализация расходится с ним, сначала меняется этот документ и только потом код.
